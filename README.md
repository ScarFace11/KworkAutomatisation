> Автоматизация рутинных заданий на платформе Творк

Бот распознаёт типы заданий, заполняет формы и отправляет ответы.  
Работает в фоне — вы просто наблюдаете.

---

## 📋 Что он умеет

- Копирует задание и вставляет в форму ответа
- Определяет тип: **обычное**, **одежда/обувь**, **косметика**, **приоритетное**
- Навигирует по форме через `Tab` — быстро и без мыши
- Обрабатывает **до 300 заданий** в цикле
- Сам исправляет ошибки в приоритетных заданиях
- Не дублирует — одно задание не возьмёт дважды
- Если клик трижды не сработал — **останавливается**, чтобы не навредить

---

## 🛠 Требования

| Компонент | Версия |
|-----------|--------|
| Python | `3.10+` |
| ОС | Windows (нужен WinAPI для раскладки) |

### Установка

```bash
git clone https://github.com/ScarFace11/KworkAutomatisation.git
cd KworkAutomatisation
pip install -r requirements.txt
```

## Запуск
```bash
python main.py
```
## 🗺️ План развития (Roadmap)
### Этап 1. Стабильность и надёжность

- [ ] **Добавить логирование в файл**
  Сейчас бот пишет только в консоль. Логи в файле помогут разбирать ошибки постфактум и отслеживать статистику по заданиям.

- [ ] **Добавить обработку неожиданных попапов**
  Иногда Творк показывает уведомления или капчу — бот должен их замечать и либо пропускать, либо останавливаться с понятным сообщением.

---

### Этап 2. Кроссплатформенность и технологии

- [ ] **Переписать на Selenium или Playwright**
  Сейчас бот привязан к активному окну браузера через `pyautogui` — нельзя свернуть, нельзя работать за компом параллельно. Selenium позволит работать в фоне и не будет зависеть от разрешения экрана.

- [ ] **Сделать кросс-платформенным**
  Уйти от WinAPI для переключения раскладки — использовать `pyperclip` или эмуляцию ввода внутри браузера. Тогда бот сможет работать на Linux и Mac.

- [ ] **Упаковать в Docker**
  С докером не нужно будет ставить Python и зависимости вручную — запустил контейнер, и бот работает.

---

### Этап 3. Удобство использования

- [ ] **Добавить конфиг-файл (YAML/JSON)**
  Вынести все настройки (типы заданий, маркеры, пути, задержки) в отдельный файл. Не нужно лезть в код, чтобы что-то поменять.

- [ ] **Сделать простой GUI**
  Окно с кнопками: «Старт», «Стоп», «Пауза». Счётчик обработанных заданий, статус, последние ошибки. Удобнее, чем смотреть в консоль.

---

### Этап 4. Интеллект и анализ

- [ ] **Добавить нечёткое определение типов заданий**
  Сейчас типы определяются по жёстким ключевым словам. Если текст чуть отличается — бот может не распознать. Добавить fuzzy matching или простой ML-классификатор.

---

### Этап 5. Тестирование и CI/CD
- [ ] **Покрыть тестами (pytest)**
  Модульные тесты на определение типов заданий, на логику обработки ошибок. Чтобы при доработках ничего не сломать.
